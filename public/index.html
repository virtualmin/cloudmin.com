Cloudmin is a virtual machine management panel for Linux hosts. Cloudmin 10 is a rewrite around libvirt, the standard Linux API for managing virtual machines, and supports QEMU/KVM. It runs inside Webmin on your own hardware, keeps every virtual hardware definition in libvirt, and adds the parts libvirt leaves to you: images, templates, jobs, permissions, consoles, snapshots, clones and backups.

Install it on a fresh Rocky Linux, AlmaLinux, Debian or Ubuntu host, download a cloud image from the catalogue or bring your own, and create a guest from one form. Cloud images are configured through cloud-init with the account, SSH keys and addressing you choose; installer ISOs boot into a graphical console. Every long operation is a recoverable job with progress, and the risky parts run in isolated workers without root.

Cloudmin GPL is free and manages one host with an unlimited number of virtual machines. Cloudmin Pro adds custom guest setup scripts, cloud backup destinations and image capture today, with tenancy planned. Both editions share one core, one API and one command line. Managing many hosts from one place, with placement and live migration, is planned for Cloudmin Connect, a separate product.

If you run Virtualmin, Cloudmin is the quickest way to get more of it: choose a Virtualmin GPL or Pro template and the hosting stack installs inside the new guest, with progress on the host and the guest’s Webmin reachable through it, even behind NAT.

Cloudmin Features

Cloudmin gives you one place to create, run, protect and reach KVM virtual machines on a Linux host. Built on Webmin, it adds the operational tools around libvirt that a host needs every day.

KVM virtual machines managed through libvirt, so virsh, virt-manager and Cockpit keep working alongside Cloudmin
A catalogue of verified cloud images for AlmaLinux, Rocky Linux, Debian, Ubuntu, Fedora and more, plus your own images and installer ISOs
Machine templates and resource plans that fill one creation form, with cloud-init accounts, SSH keys and static or DHCP addressing
Virtualmin GPL and Pro templates that install a complete hosting stack inside a fresh guest and register it with the host's Webmin
Disk snapshots and full clones with fresh identities, taken from stopped or running guests through the guest agent
Full backups with schedules and retention to local, SSH and S3 destinations, verified restore, and Pro transfers to cloud storage
Browser SSH terminals, serial consoles with recorded boot output and a graphical VNC console that works before the guest has a network
NAT, routed and isolated virtual networks, and guided host bridge creation with connectivity checks and automatic rollback
Directory, NFS, LVM and LVM-thin storage pools with volume inventory, native LVM snapshots and free-space checks before every disk operation
Live power state, guest agent, SSH and resource usage pushed to the browser over authenticated WebSockets, without polling
Delegate individual virtual machines to Webmin users with separate grants for power controls, consoles, terminals and password resets
Downloads, disk inspection, consoles and relays run in isolated systemd workers without root, and every long task is a recoverable job

Cloudmin does not build its own hypervisor stack. It uses the libvirt and QEMU packages your distribution already ships, keeps the virtual hardware definitions in libvirt, and adds the jobs, permissions, images and consoles that make a host pleasant to run. Nothing locks you in: the standard tools keep working on the same machines.

Built for safety, speed and control

Cloudmin has plenty of company, both open source and commercial. It sets out to be the panel that makes a single KVM host effortless without hiding Linux from you, and to grow into a multi-host platform on the same foundation through Cloudmin Connect.

A short path to a running guest

Install Cloudmin on a supported host, pick an image from the catalogue and click Create. The installer prepares libvirt, a NAT network, a default storage pool and firmware, and reports readiness before it calls the host done.

Built on libvirt, not around it

Cloudmin never assembles raw QEMU command lines or scrapes virsh output. Libvirt stays the source of truth for virtual hardware, networks and storage, so other tools and your own scripts see the same machines.

Safe by design

Creation, cloning, backups and restores run as durable jobs with resource reservations, progress and recovery after an interrupted controller. Unprivileged workers handle downloads, disk inspection and consoles, so a bad image cannot take the host with it.

Virtualmin inside every guest

Choose a Virtualmin GPL or Pro template and Cloudmin installs the hosting stack inside the new virtual machine, tracks progress, and opens the guest's Webmin through the host for machines behind NAT.

Open source core, unlimited guests

Cloudmin GPL manages one host with as many virtual machines as it can carry. Pro adds custom guest setup scripts, cloud backup destinations and image capture today, with tenancy to follow on the same shared core. Cloudmin Connect, planned as a separate product, will bring many hosts together.

The same API for people and scripts

The web interface, the command line and remote clients call one versioned JSON API with signed requests, Webmin permissions and audit logging. Automate creation, power control and management the way you already automate Virtualmin.
